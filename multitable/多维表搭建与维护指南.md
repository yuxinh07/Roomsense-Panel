# RoomSense 多维表 → 看板自动抓取：操作手册

## 0. 先说清楚一件事

`outputs/dashboard.html` 是**纯静态文件**，数据写死在 JS 常量里，**它本身不可能去读在线多维表**。

要"改多维表 → 看板自动变"，必须跑这套架构（`roomsense-cloud/`，本地已跑通）：

```
飞书多维表（你来维护）
      ↓ 每 30 分钟自动同步（或后台手动点一下）
Cloudflare Worker（API，持有密钥）
      ↓
D1 数据库（SQLite，聚合成看板 JSON）
      ↓
看板 HTML 打开时 fetch('/api/dashboard')
```

密钥只存在于 Worker 的 Secrets 里，**前端页面永远拿不到**。

---

## 1. 建表：只需要 4 张

`multitable/` 里导出的 7 个 CSV，用途分两类：

| 文件 | 用途 | 要不要在多维表建表 |
|---|---|---|
| `01_周销售汇总.csv` | 当前看板数字的快照 | ❌ 看板自动算 |
| `02_SKU周销量.csv` | 同上 | ❌ 看板自动算 |
| `05_平台周销售额.csv` | 同上 | ❌ 看板自动算 |
| `03_库存.csv` | **要维护** | ✅ |
| `04_SKU主数据.csv` | **低频维护**（采购价/规格变了才改） | ✅ |
| `06_销售明细_每周填写.csv` | **每周要填** | ✅ ← 核心 |
| `07_广告投放.csv` | **每周要填** | ✅ |

**在一个多维表里建 4 张数据表**（名字随便起，记住每张的 table_id）：

### 表 A：销售明细（最重要）
列名**必须完全一致**（Worker 认中文列名）：

`订单日期` | `平台` | `订单号` | `SKU` | `品类` | `销量` | `商品销售额` | `邮费收入` | `币种` | `汇率`

- 订单日期：飞书里用「日期」字段类型即可（Worker 已兼容时间戳/文本/Excel 序列号）
- 平台名要和现有看板一致：`Bunnings` / `Amazon Marketplace` / `Kmart` / `Dropshipzone` 等 12 个
- SKU 用全名：`XFKF-MA-1772-26-Q`（短名 `MA-1772-Q` 也能认，但建议统一全名）
- 金额：纯数字，不要带 `A$`、逗号、空格（Worker 会尽力清理，但别赌）
- `汇率` 列可以**整列留空**，见下一节

> **口径**：营收(AUD) = (商品销售额 + 邮费收入) × 汇率
> 商品销售额和邮费收入都填**原币种**金额，币种列写 `AUD` 或 `USD`。

---

## 1.5 USD → AUD 折算

你的结算单里有 AUD 和 USD 两种（截图里看 Temu - AU 是 AUD，Temu - US 是 USD），
系统只识别这两种币种。

### 三种填法，按优先级

| 你填了什么 | 系统怎么算 |
|---|---|
| ① 填了 `商品销售额` 和/或 `邮费收入` | `(商品销售额 + 邮费收入) × 汇率` ← **推荐，就用这个** |
| ② 只填了 `销售额`，币种是 USD | `销售额 × 汇率` |
| ③ 只填了 `销售额`，币种是 AUD 或留空 | 原值直接当 AUD，不折算 ← **旧格式，完全兼容** |

也就是说：**你原来的表（只有「销售额」一列）不用改也能继续用**，
只是那样没法把商品和邮费拆开统计。想拆就加两列。

### 汇率怎么来（优先级从高到低）

1. **行内「汇率」列**（结算单带的 Order Rate to AUD）—— **你的结算单每行都有，最准**
2. **后台 meta.fx_usd_aud** —— 兜底，万一某行漏填了行内汇率才用

后台加兜底汇率：

```sql
INSERT OR REPLACE INTO meta(key, value) VALUES('fx_usd_aud', '1.50');
```

### 三个防坑设计

- **AUD 永远不会被折算**。就算你行内「汇率」列填了 99，澳元行也不会被乘。
- **不是 USD 就报错**。如果哪天出现 EUR/GBP 行（截图里没有），营收记 0 + 看板顶部出告警条。
- **USD 缺汇率营收记 0，不会静默当 1 折算**。
  宁可让你看见数字掉了，也不要给你一个看起来正常其实是错的营收。

> 第一次配置完后，看一眼 `/api/dashboard` 返回的 `warnings` 是不是空数组。
> 有告警就说明有行没正确配。

### 表 B：库存
`SKU` | `品类` | `现有库存` | `在途` | `安全库存` | `预计到货`

### 表 C：广告投放
`周次` | `平台` | `广告活动` | `花费` | `广告销售额` | `订单数`

- 周次格式：`W35`（大写 W + 数字）

### 表 D：SKU 主数据
`SKU` | `品名` | `品类` | `规格` | `采购价` | `币种` | `安全库存天数`

> 初始化：直接把 `03` / `04` 两个 CSV 导入，A 和 C 用空表开始每周填。
> 列名建议直接复制 CSV 的表头，避免手打错字。

### 手动建表（不依赖我，5 分钟搞定）

不想等 MCP 配好，或者就想自己掌控，按下面做：

1. 飞书 → 云文档 → 新建「多维表」，起个名（比如 `RoomSense 运营数据`）
2. 左下角「+」新建数据表，一共建 4 张，分别改名：
   `销售明细` / `库存` / `广告投放` / `SKU主数据`
3. 每张表的第一行就是表头。**逐个手动改列名** —— 多维表默认第一列叫「文本」且不可删，
   把它改名成第一个列名即可，然后右侧「+」加剩下的列
4. 列类型建议：

   | 列 | 类型 | 说明 |
   |---|---|---|
   | 订单日期 | 日期 | 时间戳/文本/Excel 序列号也认，但日期类型最省事 |
   | 销量、商品销售额、邮费收入、汇率 | 数字 | 汇率留空即可 |
   | 币种 | 单选 | 选项只建两个：`AUD`、`USD` |
   | 平台、订单号、SKU、品类 | 文本 | — |

   > 类型选错不影响同步 —— Worker 读的是**值**，不是类型。
   > 但数字列用数字类型，后面排序和筛选会舒服很多。

5. 建完切到每张表，从 URL 里抠 `table=tblXXXXXXXX`，记下来（步骤 3 用）
6. 想省事：直接把 `multitable/` 下对应的 CSV **拖进多维表**，
   飞书会自动建列并识别表头。但**建完记得核对列名**，飞书偶尔会多建一列或改名字

## 2. 接线：4 个值

### 步骤 1 — 建飞书自建应用

**这一个应用，两处共用**：既给 Worker 同步数据用，也给我（飞书 MCP）帮你建表导数据用。
建一次就够，别建两个。

1. 打开 [飞书开放平台](https://open.feishu.cn/app) → 「创建企业自建应用」
2. 权限管理里勾选：
   - `bitable:app`（查看、评论、编辑和管理多维表）—— **必需**
   - `drive:file`（云文档文件）—— 想让我**新建**多维表时才需要；如果你自己建好表再加应用为协作者，可以不勾
3. 「凭证与基础信息」页拿到 **App ID** 和 **App Secret**
4. **发布一个版本**（否则权限不生效，这是最常漏的一步）

### 步骤 2 — 把应用加进多维表
打开多维表 → 右上角「···」→「添加文档应用」→ 搜你刚建的应用名 → 给**可编辑**权限。

> 漏了这步会报 `permission denied` / `91402`，是最常见的坑。
> 如果这个多维表是我帮你新建的，应用自动就有权限，这步可以跳过。

### 步骤 2.5 — 把凭证填进 MCP 配置（让我能帮你建表导数据）

配置文件：`~/.workbuddy-ai/mcp.json`，已经写好了，只差两个值：

```json
{
  "mcpServers": {
    "lark-mcp": {
      "command": "npx",
      "args": [
        "-y", "@larksuiteoapi/lark-mcp", "mcp",
        "-a", "REPLACE_WITH_YOUR_APP_ID",
        "-s", "REPLACE_WITH_YOUR_APP_SECRET",
        "-t", "preset.base.default,preset.base.batch"
      ]
    }
  }
}
```

把 `REPLACE_WITH_YOUR_APP_ID` 和 `REPLACE_WITH_YOUR_APP_SECRET` 换成步骤 1 拿到的值，然后：

1. 打开 WorkBuddy 的**连接器管理**页面
2. 右上角「自定义连接器」入口 → 找到 `lark-mcp` → 点**信任**
3. 重启 WorkBuddy

装好后我可以帮你：新建多维表 → 建那 4 张数据表（列名自动设好）→ 把导出的 CSV 批量灌进去，
**你连手工建表都不用做**。

> `-t` 里两个 preset 的分工：`preset.base.default` 负责建表/列字段/读写单条，
> `preset.base.batch` 负责批量灌记录（121 行 SKU 周销量靠它，一次能塞几百行）。
> 两个都要，少一个就没法批量导。

### 步骤 3 — 拿 table_token 和 table_id
多维表 URL 长这样：

```
https://xxx.feishu.cn/base/BascnXXXXXXXX?table=tblYYYYYYYY&view=vewZZZZ
                              └─── table_token ────┘        └── table_id ──┘
```

4 张表各切一次，记下各自的 `tbl...`。

### 步骤 3.5 — 先自检，别急着注入

拿到凭证后先跑自检，**不用先部署到 Cloudflare** 就能验证接没接对：

```bash
node tools/check_feishu.mjs \
  --app-id=cli_xxxxxxxx \
  --app-secret=xxxxxxxx \
  --token=BascnXXXXXXXX
```

它会一次性告诉你：

1. 鉴权通不通（App ID/Secret 对不对）
2. 多维表能不能读到（最常见的失败是**没把应用加为协作者**）
3. **列出所有数据表的 table_id** —— 不用你一个个去 URL 里抠
4. 目标表的列名有没有对上（差一个字都会报出来）
5. 打印一行原始数据，让你看日期是不是时间戳、金额是不是带符号

全绿再往下走。加 `--debug` 看原始 API 返回。

### 步骤 4 — 注入 Secrets（**不要写进任何代码文件**）

密钥只走两条路：环境变量，或 `wrangler secret put`。**脚本里一个密钥都不存**，
所以 `setup_feishu.sh` 可以放心提交到 GitHub。

把值写进 `tools/.env.feishu`（模板见 `tools/.env.feishu.example`，
这个文件已在 `.gitignore` 里，不会进版本库）：

```bash
cp tools/.env.feishu.example tools/.env.feishu
# 然后编辑它，填真实值
```

跑一次注入：

```bash
bash tools/setup_feishu.sh
```

脚本会校验必填项、逐个注入、列出已配置的 Secrets，最后打印 3 条手动命令
（部署 / 触发同步 / 看日志）。

手动注入也行：

```bash
npx wrangler secret put FEISHU_APP_ID        # cli_xxxxxxxx
npx wrangler secret put FEISHU_APP_SECRET
npx wrangler secret put FEISHU_TABLE_TOKEN   # BascnXXXXXXXX
npx wrangler secret put FEISHU_TABLE_ID      # 销售明细表 tbl...
npx wrangler secret put FEISHU_TABLE_ID_INV  # 库存表 tbl...（可选）
npx wrangler secret put FEISHU_TABLE_ID_ADS  # 广告表 tbl...（可选）
npx wrangler secret put FEISHU_TABLE_ID_SKU  # SKU主数据 tbl...（可选）
npx wrangler secret put ADMIN_TOKEN          # 后台写入口令，自己定一个
```

后 3 个是可选的：配了就同步，不配就跳过，互不影响。

## 3. 自动抓取怎么发生

- **自动**：`wrangler.toml` 里已配 `crons = ["*/30 * * * *"]`，每 30 分钟同步一次
- **手动**：后台 `/admin.html` 第 ④ 区点「立即同步」，或 `curl -X POST https://<你的域名>/api/sync/feishu -H "X-Admin-Token: <ADMIN_TOKEN>"`
- **看板**：每次打开页面都重新 `fetch('/api/dashboard')`，所以同步完刷新即生效

同步策略（避免重复/丢失）：

| 表 | 策略 |
|---|---|
| 销售明细 | 删掉 `source='feishu'` 的行再全量写入 → **CSV 导入的历史数据不会被误删** |
| 库存 / SKU 主数据 | 按 SKU 覆盖更新 |
| 广告投放 | 全量替换（多维表是唯一来源时最干净） |

## 4. 关键：渐进接管，别一次性切

现在库里的数字是以 **overrides（人工矫正值）** 形式落库的，优先级**高于**自动聚合。
所以你一开始往多维表填明细，看板数字**不会立刻变** —— 这是故意的，防止新旧数据打架。

切换节奏建议（每次切一块，对上了再切下一块）：

1. **先切平台**：填一周明细 → 后台第 ③ 区删掉 `platData` 这个 override → 看平台占比对不对 → 对上了继续
2. **再切周趋势**：删 `weekly.W35`（以及其它 `weekly.W##`）→ 看各周销售额
3. **再切 SKU 趋势**：删 `skuWeek.<SKU>.<W##>`（几十条，可以一次全删）
4. **最后切库存/建议**：删 `invData` / `invSuggestData`
5. **品类**：删 `catData`

overrides 清空后，看板就 100% 由多维表明细驱动。

> 任何一步发现数字对不上，把 override 加回去就行，不会破坏数据。

---

## 5. 每周你要做的事（最终态）

1. 往「销售明细」表里贴本周订单（各平台后台导 CSV → 整理成 10 列 → 粘进多维表）
   - 商品销售额 / 邮费收入分开填，币种别漏（澳元行填 `AUD`，美元行填 `USD`）
   - 汇率列留空即可，用后台配的全局 `fx_usd_aud`
2. 往「广告投放」表填本周各平台花费和广告销售额
3. 「库存」表更新现有库存 / 在途（有到货或盘点时改）
4. 美元汇率波动大时，更新一下 meta 里的 `fx_usd_aud`（或按周加 `fx_usd_aud.W35`）
5. 什么都不用点 —— 30 分钟内看板自动更新

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `未配置飞书 Secrets` | 4 个必需值没配全 | `npx wrangler secret list` 检查 |
| `飞书鉴权失败` | App ID/Secret 错了，或应用没发布版本 | 回开放平台发布版本 |
| `飞书读取失败(permission denied)` | 应用没加进多维表协作者 | 步骤 2 |
| 同步成功但看板没变 | overrides 还在覆盖 | 按第 4 节删对应 override |
| SKU 在库存表里匹配不上 | 短名/全名混用 | 统一用全名 `XFKF-MA-1772-26-Q` |
| 销售额变成 0 | 单元格带了 `A$`/逗号/空格 | 改成纯数字（Worker 会尽力清理，但别赌） |
| 美元行营收变成 0 | 没配 `fx_usd_aud` | 后台 meta 加 `fx_usd_aud`；看 `/api/dashboard` 的 `warnings` |
| 美元营收明显偏大/偏小 | 用了过期的全局汇率 | 按周加 `fx_usd_aud.W35`，或在行内 `汇率` 列直接填 |
| 澳元行也被乘了汇率 | 不会（AUD 恒为 1），若出现请报 bug | — |
| CSV 导入后中文列名对不上 | 文件没带 UTF-8 BOM | 用 `tools/export_for_multitable.mjs` 重新导出（已自动加 BOM） |

## 7. 部署到 Cloudflare

**先部署，再接线**。没部署的话飞书接了也没地方跑。

### 7.1 授权（两种方式，选一个）

**方式 A：浏览器点一下（推荐，最省事）**

```bash
cd roomsense-cloud
npx wrangler login
```

会自动开浏览器，登录 Cloudflare 后点「Allow」即可。
如果没自动开，终端会打印一个 URL，手动复制到浏览器。

**方式 B：API Token（headless / 服务器用）**

去 Cloudflare Dashboard → My Profile → API Tokens → Create Token，
用「Edit Cloudflare Workers」模板，额外加上 D1 的编辑权限。
然后：

```bash
export CLOUDFLARE_API_TOKEN=xxxxxxxx
```

> **不要给全局管理员 Token**，权限最小化即可。

### 7.2 建库 + 建表 + 灌数据

```bash
npx wrangler d1 create roomsense-db      # 输出里有 database_id
```

把 `database_id` 填进 `wrangler.toml` 的 `database_id = "..."` 处，然后：

```bash
npx wrangler d1 execute roomsense-db --remote --file=schema.sql
npx wrangler d1 execute roomsense-db --remote --file=seed.sql
```

`seed.sql` 会把现有看板数字原样灌进去，所以部署完第一眼看到的跟现在一模一样。

### 7.3 注入 Secrets + 部署

```bash
bash tools/setup_feishu.sh     # 或手动 npx wrangler secret put ...
npx wrangler deploy
```

部署完会给一个地址，例如 `https://roomsense-dashboard.<子域>.workers.dev`：

- `/` → 看板
- `/admin.html` → 数据录入后台
- `/api/health` → 健康检查（先 curl 这个确认活着）

### 7.4 验证同步

```bash
curl -X POST https://<你的域名>/api/sync/feishu -H "X-Admin-Token: <你的口令>"
```

返回 `{"ok":true,"synced":{"sales":N,"inventory":N,"ads":N,"sku":N,...}}` 即通。
